What is copied into at_elements

On launch the app writes three groups of files under Library/Application Support/at_elements. Two of those writes create the parent folder. The third dies while creating templates, before a single template file is unpacked.

The folder on disk

The fatal error is the mkdir of templates. ZipStore.unpack has not run, so none of those template files are on disk.

Two writers at once

Main thread

ManifestBootView.task, after the first frame

  1. DemoSeeder mkdirs at_elements/saved and copies the .ats files.
  2. CustomsSeeder mkdirs at_elements/customs and copies the three .ati files.
  3. Then it waits for the manifest queue.

Manifest queue

started in App.init, before the view task

  1. reloadAll calls AssetTemplates.prepare first.
  2. createDirectory of at_elements/templates returns POSIX 13. The process stops here.
  3. Unpack of template.basic.atp does not start.

read in place, never copied
packs/assorted.bgs.atp, packs/zalivka.space1.atp, and every other .atp except template.basic. Backgrounds and items in those packs are read from the zip inside the app.
